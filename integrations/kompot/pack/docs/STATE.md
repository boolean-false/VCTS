# Состояние и обновление таблиц

`K.state(initial)` хранит значение в компоненте. `K.new_state(initial)` создаёт
состояние вне композиции, например для модели окна. Чтение `.value` во время
композиции подписывает компонент на изменения; `:peek()` читает без подписки.

```lua
local K = require "kompot:kompot"
local UI = require "kompot:ui"

local Screen = K.component(function()
    local player = K.state({ name = "Петя", health = 100, coins = 0 })
    K.Column({ spacing = 8 }, function()
        K.Text(player.value.name .. ": " .. player.value.health)
        UI.Button({
            text = "Получить урон",
            on_click = function()
                player:update_field("health", function(health)
                    return math.max(0, health - 10)
                end)
            end,
        })
    end)
end)

K.preview("Игрок", { width = 360, height = 180, theme = UI.theme() }, Screen)
```

## Замена значения

`state.value = value` и `state:set(value)` заменяют всё значение.
`state:update(fn)` вычисляет новое значение из предыдущего и передаёт его в `set`.

Изменение поля существующей таблицы не уведомляет UI:

```lua
local old = player:peek()
old.health = 90
player.value = old -- ссылка прежняя, уведомления не будет
```

Для таблиц используйте новые значения или методы ниже. Все они работают
через `State:set`, сохраняя обычную подписку и пользовательскую функцию сравнения.

## Несколько полей: patch

```lua
player:patch({ health = 90, level = 5 })
```

Метод создаёт новую поверхностную копию и заменяет перечисленные поля.
Остальные поля сохраняются. Исходная таблица и таблица изменений не изменяются.
Функции в patch сохраняются как значения и не вызываются.

`patch` работает только со State, содержащим таблицу; аргумент тоже должен
быть таблицей. При неверном типе возникает понятная ошибка.

## Одно поле: update_field

```lua
player:update_field("health", 90)
player:update_field("coins", function(coins)
    return coins + 100
end)
```

Второй аргумент - новое значение либо функция от предыдущего значения поля.
Функция вызывается один раз. Для отсутствующего поля она получает `nil`.
Вычисляющая функция должна возвращать новое значение, не изменяя старую таблицу.
Если она завершится ошибкой, метод не присвоит новое значение в State.

Метод создаёт новую таблицу и уведомляет подписчиков через `set`.
Ключ может быть любым допустимым ключом Lua, включая числовой индекс массива.
`nil` и NaN в качестве ключа запрещены. State должен содержать таблицу.

Удаление поля:

```lua
player:update_field("temporary", nil)
player:update_field("temporary", function() return nil end)
```

Записать функцию как значение поля можно через `patch`:

```lua
player:patch({ on_damage = callback })
```

В `update_field` функция всегда означает вычисление нового значения.

## Обычные таблицы: K.copy

```lua
local next_player = K.copy(old_player, { health = 90 })
local duplicate = K.copy(old_player)
```

Первый аргумент должен быть таблицей. Второй - необязательная таблица замен.
Результат всегда новая обычная таблица; метатаблица исходника не переносится.
Массивные элементы, именованные поля и значения `false` копируются как обычно.
Изменения могут добавлять поля или заменять существующие.

## Вложенные таблицы

Копирование **поверхностное**: вложенные значения сохраняют ссылки.
Переданная вложенная таблица заменяется целиком; глубокого слияния нет.

```lua
-- armor не сохранится: stats заменяется целиком.
player:patch({ stats = { health = 90 } })

-- Изменяется health, armor и другие поля stats сохраняются.
player:update_field("stats", function(stats)
    return K.copy(stats, { health = 90 })
end)
```

Для нескольких вложенных обновлений:

```lua
player:update(function(old)
    return K.copy(old, {
        name = "Петя",
        stats = K.copy(old.stats, { health = 90 }),
    })
end)
```

Это явные изменения: `patch` не интерпретирует строки вроде `"stats.health"`
как пути и не угадывает правила объединения массивов.

`patch({ field = nil })` и `K.copy(old, { field = nil })` не удаляют поле:
Lua не сохраняет такую запись в таблице изменений. Для удаления используйте
`update_field(key, nil)` или удалите поле у новой копии внутри `update`.

Даже пустой patch и присваивание прежнего значения поля создают новую таблицу.
По умолчанию State сравнивает значения через `==`; для обычных таблиц новая
ссылка означает изменение. Дополнительного глубокого сравнения нет.
Если State создан с пользовательским `eq`, он может подавить замену и уведомление.

## Форма: K.form

Для фиксированного набора независимых полей используйте `K.form(initial)`:

```lua
local Settings = K.component(function()
    local form = K.form({ name = "", enabled = true, size = 10 })
    UI.TextField({ state = form.name, label = "Имя" })
    UI.Switch({
        text = "Включено",
        checked = form.enabled.value,
        on_change = function(value) form.enabled.value = value end,
    })
    UI.Slider({
        label = "Размер", min = 1, max = 20, value = form.size.value,
        on_change = function(value) form.size.value = value end,
    })
end)
```

Результат - запомненная таблица отдельных State: `form.name`, `form.enabled`,
`form.size`. Каждый потребитель подписывается на свои поля. Вызов `K.form`
сам по себе не подписывает владельца на значения всех полей.

Начальные значения применяются только при создании. Новая таблица `initial`
при следующей композиции не сбрасывает введённые данные. Функция в поле
является обычным значением, а не инициализатором. Вложенная таблица является
значением одного State; глубоких реактивных прокси нет.

Набор ключей должен оставаться неизменным в течение жизни формы. Попытка
добавить или убрать поле приводит к ошибке `K.form schema changed`.
Для другой схемы или полного сброса создайте новую область с другим ключом:

```lua
local generation = K.state(0)
UI.Button({text = "Сбросить", on_click = function()
    generation.value = generation:peek() + 1
end})
K.key(generation.value, function()
    local form = K.form({ name = "", enabled = true })
    UI.TextField({ state = form.name })
end)
```

Сама таблица полей предназначена для чтения; не добавляйте и не заменяйте
её State вручную. Меняйте их `.value` или используйте методы State.
Автоматические валидация, reset, submit и dirty-флаги в этот API не входят.

## Время жизни и диагностика хуков

Хуки `state`, `remember`, `effect` и анимации должны сохранять порядок вызовов
в своей области композиции. Для переменного списка и условных дочерних областей
используйте устойчивые `K.key` или `K.component`.

Если компонент удалён, его локальное состояние удаляется вместе с ним.
Чтобы закрытая вкладка сохраняла данные, храните состояние в родителе или
внешней модели. `patch` и `update_field` не меняют эти правила времени жизни.

С версии 1.2.0 runtime проверяет вид и количество хуков в каждой области.
Базой является последняя успешная композиция. Подмена `state` на `remember`,
добавление или удаление хука в той же области вызывает ошибку
`Hook order changed in component ...` с указанием слота и ожидаемого вида.
Анимации, формы, состояния прокрутки и другие публичные хуки различаются
по своим именам; внутренний `remember` не создаёт ложного несовпадения.

```lua
-- Ошибка: число хуков в одной области зависит от visible.
if visible.value then
    local count = K.state(0)
end

-- Правильно: условное содержимое имеет отдельную область.
if visible.value then
    K.key("counter", function()
        local count = K.state(0)
        K.Text(tostring(count.value))
    end)
end
```

Проверка типов и количества включена всегда. Подробные места вызова и списки
`Previous`/`Current` включаются отдельно:

```lua
K.mount({ content = Screen, theme = UI.theme(), hook_diagnostics = true })
```

Тот же параметр принимает `K.App.new`. В превью диагностика мест вызова
включена по умолчанию; `K.preview(..., {hook_diagnostics = false}, ...)`
отключает только сбор подробных мест, сохраняя защиту слотов.

Проверка сравнивает виды и количество, а не смысл всех вызовов: перестановка
двух `K.state` с тем же количеством слотов может остаться незамеченной.
Стабильные ключи и порядок вызовов всё равно обязательны.
Не вызывайте хуки внутри инициализаторов `remember`/`state`: инициализатор
выполняется только при создании, а хуки должны повторяться при композиции.

Эффекты не запускаются для области, композиция которой завершилась ошибкой.
Вновь созданные в неуспешной попытке слоты освобождаются; предыдущие
успешные State сохраняются. После восстановления правильного порядка
компонент может продолжить работу; для новой структуры используйте новый ключ.
