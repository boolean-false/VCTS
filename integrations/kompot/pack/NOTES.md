## UI VoxelCore: трансформации, прозрачные слои и сглаживание — 2026-10-02

Цель будущей доработки движка: общая поддержка трансформаций любого UI-поддерева,
включая обычные XML/Lua-интерфейсы, текст, поля ввода и вложенные контейнеры.
Она должна позволить Kompot отказаться от снимков на чёрной/белой подложке
и программного поворота этих снимков в бэкенде.

- **Трансформации UI-узлов.** Матрица переноса, масштаба, поворота и pivot;
  композиция матриц предков в DrawContext/Batch2D. Layout и визуальное
  преобразование независимы. Сохранять дробные координаты при отрисовке;
  pixel snapping сделать осознанным режимом. Сейчас UINode::calcPos округляет
  координаты, а Image::draw не использует доступный в Batch2D поворот.
- **Ввод и обрезка.** Hit testing, drag и координаты редактора переводить
  обратной матрицей в локальную систему. Учитывать вложенные clip и scroll.
  Scissor подходит для осевых прямоугольников; повёрнутым clip нужны маски
  или stencil с согласованным сглаживанием. Проверить каретку и выделение.
- **Прозрачные GPU-слои.** Чёткий контракт premultiplied alpha, прозрачная
  очистка, корректное накопление alpha и композиция слоя. Существующий
  glBlendFunc(SRC_ALPHA, ONE_MINUS_SRC_ALPHA) применяет эти коэффициенты
  также к alpha и не подходит как общий контракт прозрачного буфера.
  Согласовать загрузку обычных текстур, фильтрацию и экспорт Canvas;
  простая глобальная замена blend-функции нарушит существующие ресурсы.
- **Качество.** Отдельные настройки сглаживания геометрии и nearest/linear
  для изображений; sampler на отрисовку, без изменения общей текстуры.
  У окна есть настройка samples, но Framebuffer для UI сейчас одно-сэмпловый
  и использует NEAREST. Добавить MSAA с resolve на GPU и/или аналитическое
  покрытие фигур. MSAA не устраняет уже записанную в текстуру лесенку alpha.
- **Жизненный цикл.** Порядок зависимых render pass, переиспользование буферов,
  инвалидация при изменении содержимого отдельно от матрицы. Обычный поворот
  не должен требовать чтения GPU-пикселей на CPU или нового FBO каждый кадр.
  Исправить согласование Batch2D с реальным GL binding при resize/create
  текстур: именно это потребовало текстурных подложек в Kompot 1.2.1.
- **Интеграция.** Экспортировать возможности через XML/Lua и явный capability
  API. Kompot выбирает нативный путь при наличии полного контракта
  (трансформации, clip, alpha, ввод), а на старом движке использует fallback.
  Не применять одновременно программное сглаживание и нативный поворот
  одного слоя. Программный compositor сохранить для старых движков,
  `Canvas:image` и независимого рендера; удалить его можно только после
  прекращения поддержки всех этих путей или их полноценной замены.

Текущее сглаживание Kompot: точная площадь пересечения пикселя с границей
повёрнутого слоя, выборка 4 × 4 внутри неоднородных участков изображения,
усреднение premultiplied RGBA; одноцветные области проходят быстрым путём.
Это CPU-растеризация, а не замена будущим GPU-трансформациям. При глубокой
вложенности сохраняется стоимость и накопление фильтрации промежуточных слоёв.

Проверки для будущего движка: белая фигура на контрастном фоне при малых углах,
полупрозрачные изображения без ореолов, вложенные повороты/масштабы/clip,
групповая alpha, pixel-art и текст, ввод в повёрнутые контролы, resize буферов,
ресурсная стабильность при долгой анимации. Основные файлы: `UINode.cpp`,
`Image.cpp`, `Container.cpp`, `Frame.cpp`, `DrawContext.cpp`, `Batch2D.cpp`,
`Framebuffer.cpp`, `Texture.cpp` и UI-шейдеры в репозитории VoxelCore.

## План Kompot 1.2.0 - 2026-10-01

Цель версии: удобное обновление состояния и понятные ошибки при работе с хуками.
Ниже актуальный план; заметки ревью далее сохраняют исторический контекст,
а упомянутые там версии и номера строк могут быть устаревшими.

### Включить в 1.2.0

- **`State:patch`, `State:update_field`, `K.copy`.** Уже реализованы в рабочей
  копии. Поверхностное копирование, явные вложенные обновления, удаление поля
  через `update_field(key, nil)`. Дополнены тесты, галерея и AI-справочник.
- **Диагностика порядка хуков - реализовано.** Проверять вид и количество публичных хуков
  в одной области между успешными композициями. Сообщать компонент, место
  вызова, ожидаемый и фактический хук; пояснять использование `K.key` или
  отдельного компонента для условной ветки. Учитывать, что `state`, анимации
  и другие публичные хуки внутри используют `remember`: внутренние вызовы
  не должны превращаться в ложные несовпадения. Ошибка должна обнаруживаться
  до использования несовместимого слота. Условное добавление/удаление областей
  с собственными ключами остаётся допустимым. Подробные стеки и трассировка -
  только при включённой диагностике, чтобы не увеличивать стоимость обычного кадра.
- **`K.form(initial)` - реализовано.** Хук для фиксированного набора полей: возвращает
  запомненную таблицу отдельных State, например `form.name` для TextField и
  `form.enabled` для Switch. Создавать поля через `K.new_state` внутри одного
  `remember`, а не через переменное число `K.state` в цикле. Начальные значения
  применяются при создании; повторная композиция не сбрасывает ввод.
  Изменение схемы во время жизни формы не поддерживать в первой версии;
  новую форму создавать в новой области `K.key`. Вложенные значения полей
  остаются обычными значениями State, без глубоких прокси. Автоматическую
  валидацию, dirty-флаги, submit и общий reset пока не включать.

Для новых возможностей обновлены аннотации ядра и Lens, документация,
AI-справочник и живые примеры. Версия Kompot в исходниках установлена в 1.2.0.
Сведения об отложенных возможностях ниже остаются актуальны.

### После 1.2.0

- **Чистые функции списков `K.list`.** Рассмотреть `append`, `insert`,
  `remove_at`, `remove_if`: обычная плотная последовательность на входе,
  новая таблица на выходе, без мутации исходника и без зависимости от State.
  Использовать через `items:update(fn)`. Для изменения элемента уже есть
  `update_field(index, value_or_fn)`. Различать удаление со сдвигом элементов
  и присваивание nil, которое оставляет дыру. Добавлять после нескольких
  реальных примеров списков; отдельный `state_list` пока не нужен.
- **Инспектор Lens.** После диагностики хуков показывать дерево компонентов,
  слоты, значения State/remember и причины перекомпозиции. Первая версия -
  только просмотр, без редактирования состояния. Снимки получать по запросу;
  предусмотреть циклы таблиц, функции, объекты движка и ограничения размера.
  Не сериализовать всё дерево на каждом кадре обычного превью.
- **Предупреждения о прямой мутации State.** Начать с анализа типов в Lens/
  LuaLS для записей вроде `player.value.health = 90`, предлагать `patch` или
  `update_field`. Не использовать только регулярные выражения: алиасы и
  обычные таблицы требуют различения. Runtime-снимки и глубокие прокси пока
  отложить из-за стоимости и изменения семантики Lua-таблиц.
- **Настоящий derived state.** Добавлять, если нужны общие вычисления с
  автоматическими зависимостями и уведомлением только при изменении результата.
  Сначала определить очистку подписок, динамические зависимости, циклы,
  ленивый/немедленный пересчёт и equality. Для тяжёлого вычисления с явными
  ключами сейчас достаточно `K.remember(fn, ...)`; не вводить `derived`
  как простой псевдоним с более широкими обещаниями.
- **Именованное shallow equality.** Рассмотреть при реальной необходимости
  подавлять обновления новых таблиц с теми же полями. `reference` уже покрыто
  стандартным сравнением State. `deep` требует решения по циклам, метатаблицам
  и стоимости обхода. `never` нельзя реализовать одним пользовательским `eq`:
  `State:set` возвращается при `old == new` до вызова компаратора; такая политика
  потребует отдельного изменения контракта уведомлений.
- **Расширения форм.** Общий reset, валидация и отслеживание изменений - только
  после использования простого `K.form` в настоящих формах. Уточнить, является
  ли reset набором отдельных уведомлений или нужна пакетная транзакция.

### Не добавлять без новых требований

- `remember_value`: `K.remember` уже принимает готовое значение; функция
  инициализации остаётся предпочтительной для ленивого создания объектов.
- `K.each`: обычный `for` и явный `K.key` уже выражают обход и идентичность.
- `K.list_copy`: поверхностное копирование массива уже делает `K.copy`.
- `State:set_field`: присваивание уже покрыто `update_field`.
- Deep merge, строковые пути полей и глубокая реактивность таблиц:
  вложенное обновление через `K.copy` остаётся явным и предсказуемым.
- Новые перегрузки Box/Row/Column: формы `Component(content)` и
  `Component(modifier, content)` уже поддерживаются. Сохранять их совместимость
  и объяснять в справке вместо добавления нового API.

Замеры ниже сняты в headless-движке с бэкендом-регистратором
(`kompot/backend/recorder.lua`), в миллисекундах на кадр.

## Производительность

- **Прокрутка перерисовывает всё содержимое.** Координаты примитивов
  считаются от начала области обрезки, поэтому сдвиг прокрутки меняет каждый
  примитив внутри неё, и кэш отрисовки не срабатывает (1000 строк - около
  1.5 мс). Вариант исправления: вложенный контейнер содержимого, который
  двигает бэкенд, а примитивы отсчитываются от него.
- **Полная перекомпозиция стала дороже примерно на 15%** (600 узлов:
  2.1 → 2.4 мс) из-за учёта кэша раскладки и отрисовки при сплошных промахах.
  Локальные изменения стали быстрее примерно в 6 раз.
- **Пропуск компонентов блокируют замыкания.** Свойства сравниваются
  поверхностно; модификаторы - по слоям, но функции только по ссылке. Новый
  `on_click` или `content`, созданные в родителе, делают перезапуск ребёнка
  неизбежным. Можно добавить хук стабильного обработчика (аналог
  `useEvent`): ссылка постоянна, вызывает последнюю версию.
- **`collect_overlays` проходит всё дерево на каждой раскладке**
  (`core/layout.lua:758`), даже когда все размеры берутся из кэша; отдельно
  не замерялось. Можно собирать слои во время композиции.
- **Ленивый список: `for i = 1, first - 1`** (`core/layout.lua:742`) на
  каждой раскладке - O(номер первой видимой строки) вызовов `p.key(i)`.
  В конце списка из 100 000 строк это заметно.
- **Устаревшие подписки удалённых узлов.** Узел, прочитавший State при
  раскладке, остаётся подписчиком, пока его не соберёт GC (слабые ключи).
  Запись в такой State запускает лишний проход раскладки, в котором все
  узлы берутся из кэша. На корректность не влияет.
- **`Modifier.chain` копирует всю цепочку** при каждом вызове
  (`core/modifier.lua:16`), то есть O(n²) по длине цепочки.
- **Бэкенд VoxelCore каждый кадр перебирает все элементы**
  в `text_focused()` и `field_under_mouse()` (`backend/voxelcore.lua:1222`,
  `:1247`). Стоит вести отдельный список полей ввода.

## Надёжность

- **`editor_state`/`presentation` на обычном VoxelCore.** Бэкенд делает
  `assert` внутри `Backend:apply` (`backend/voxelcore.lua:849`). Ошибка
  повторяется каждый кадр, а применение списка обрывается на середине.
  Документация (`docs/TEXT_INPUT.md`) требование описывает, а справочник
  скрывает такие примеры, но мод, использующий их напрямую, сломает весь
  экран. Лучше откатываться к нативному полю и сообщать ошибку через
  `rt:report_error` один раз.
- **Повторно открытый макет без `dispose()`.** Документ макета
  переиспользуется, и забытый хост снова оживает - на экране два
  интерфейса. Блокировка Tab теперь снимается правильно
  (`backend/inventory_lock.lua`), но сам дубль можно было бы замечать:
  второй `K.mount` в тот же `target` при живом первом - предупреждение.
- **Порядок хуков - исправлено в 1.2.0.** Виды и количество проверяются
  до использования несовместимого слота; подробные места вызова доступны
  через `hook_diagnostics`. Смена двух хуков одного вида может быть не обнаружена.
- **`K.provide` без ключа - позиционная область** (`core/runtime.lua:418`).
  Две ветки `if` с разным содержимым `provide` на одном месте делят слоты
  хуков. Для компонентов это закрыто сравнением функции, для групп - нет.
- **Эффект области, удалённой в том же кадре,** всё равно выполнится в
  `Runtime:commit` (`core/runtime.lua:799`), и его очистка не будет вызвана.
  На практике возможно только в ленивых списках при нескольких проходах
  раскладки за кадр.
- **Идентичность областей ввода позиционная.** Без `K.key` вставка
  элемента выше переносит фокус и hover на соседа. Можно предупреждать в
  режиме разработки о списках компонентов без ключей.
- **Текстуры Canvas нельзя выгрузить.** Имена переиспользуются через пул,
  но пик числа холстов остаётся в памяти до `app.reset_content()`.

## Тесты и инструменты

- **Визуальные тесты ждут по времени** (`app.sleep`), а не по кадрам.
  На медленном кадре событие ввода может не попасть ни в один кадр.
  В `tests/visual/window.lua` ожидание переведено на кадры приложения
  (`frames()`); больше всего `app.sleep` в `game_ui.lua`, `text_input.lua`,
  `gallery.lua` и `text_presentation.lua`.
- **Визуальные тесты нельзя запускать параллельно.** Фоновые окна движка не
  получают фокус ОС (`test.fill` не вводит текст), а тайловый WM уменьшает
  окна (например, до 608×311).
- **`text_presentation` требует пропатченного движка** и на обычной сборке
  падает, а не пропускается. Можно проверять
  `backend:supports_text_presentation()` и печатать `skipped`.
- **LuaLS ложно ругается** на `K.remember(fn, a, b)`: аннотация
  `fun<T>(initial: fun(): T, ...: any): T` (`annotations/kompot.lua:451`)
  с generic и `...` не разбирается.
- **Метрики шрифтов для превью пусты** (`core/font_metrics.lua`), превью
  меряет текст приблизительно. Снимаются через
  `tests/visual/run.sh font_metrics`.
- **Шрифт экрана ошибки** (`core/app.lua:110`, `kompot_12`) оставлен
  жёстко заданным намеренно: шрифт ядра есть всегда, а шрифт темы может
  быть причиной ошибки.

--------------------------------
Выяснено при разработке бэкенда:

- UV текстур холста (`Canvas`) начинаются снизу: четверти круга для
  скруглений берутся регионами с перевёрнутой осью v, пользовательские
  холсты - с регионом `{0, 1, 1, 0}`.
- Контейнер нулевого размера рисуется линией в 1 px. Части нулевой
  площади не создаются.
- Атрибут `text-color` у `textbox` в XML игнорируется - задаётся свойством
  `textColor`.
- `container:add` ничего не возвращает; элементы ищутся по id через
  `Document`. Обработчики - через `DATA` второго аргумента.
- Метка с `autoresize` измеряет текст синхронно, но только после первой
  отрисовки шрифта.
- Порядок наложения: свойство `zIndex` и `container:refresh()`.
- Метка не рисует пробелы в начале текста. В многоцветном тексте они
  превращаются в смещение отрезка.
- Для корректной загрузки страниц Unicode и отступов векторных глифов
  используйте сборку VoxelCore с исправлением векторных шрифтов.
- Размер окна в тестах может поменять оконный менеджер уже после запуска.
  Визуальные тесты рисуют превью по одному в углу и ждут, пока размер
  устоится.


## Производительность

Замеры на демо (≈1500 примитивов на экране, 165 FPS в окне):

| Этап | Время кадра |
|---|---|
| Композиция (частичная) | 0,3 мс |
| Раскладка и отрисовка | 0,7 мс |
| Применение к GUI движка | 0,4 мс |

Ядро: 600 узлов - полная композиция, раскладка и отрисовка за ≈2,4 мс.
Изменение одного компонента на экране из 1000 компонентов (~4000 узлов) -
≈0,3 мс: остальные берут размеры и примитивы из кэша.
Если ничего не изменилось, кадр почти бесплатный: нет грязных областей, нет
раскладки. `app.stats` содержит счётчики и скользящие средние времени.
