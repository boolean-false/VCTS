# VCTS: короткое руководство для автора и нейросети

VCTS компилирует TypeScript в LuaJIT Lua для VoxelCore. Исходники движка для
обычной разработки не нужны. Опирайтесь на типы SDK, публичные контракты модов,
примеры и результаты запуска. Не угадывайте неизвестные функции движка.

## Начало работы

Установите Node.js 22+ и зависимости скачанного с GitHub VCTS (`npm ci`).
Если хотите вызывать `vcts` из любой папки, один раз выполните `npm link`
из папки VCTS. После этого просто запустите `vcts`: откроется меню.
Если нет прав на глобальную папку npm, на macOS/Linux выполните
`npm_config_prefix="$HOME/.local" npm link` и добавьте
`export PATH="$HOME/.local/bin:$PATH"` в настройки терминала (`~/.zshrc` для zsh).
В нём можно создать проект, установить его npm-зависимости, подключить пак,
настроить папку установки, собрать мод и запустить тесты или watch.
Стрелки/Enter выбирают действие, Esc возвращает назад; в полях пути Tab
дополняет имя, Esc/Ctrl+C отменяют ввод. Watch останавливается через Q/Esc/Ctrl+C.
Проект находится автоматически в текущей папке или выше. Через обычные команды
можно работать как прежде; в неинтерактивной среде запуск без аргументов выводит
справку. В установленном проекте меню также открывается через `npm exec -- vcts`.

Из папки VCTS создайте проект:

```sh
node tools/vcts.cjs init /path/to/my_mod --kind mod --id my_mod
```

Откройте созданную папку в VSCode или WebStorm и выполните `npm install`.
Дальше все команды выполняются из папки своего проекта:

```sh
npm run check
npm run build
npm run watch
npm test
```

`src/<id>` содержит TS; `vendor/sdk` — типы движка; `vcts.config.json` — настройки.
Для обычных ресурсов создайте `content` и добавьте в `assets`:
`{"from":"content","to":"content/my_mod"}`. Это стандартные JSON/XML/TOML,
модели и текстуры VC. Автоматической полной проверки форматов ресурсов пока нет.

## Готовый мод с Lua API

Подключите папку обычного контент-пака, а не его исходный TS-проект:

```sh
npm exec -- vcts add "/path/to/game/content/rail_core"
```

Команда добавляет корневую `dependencies`, зависимость собственных паков и
`compilerOptions.paths` всех TS-программ для подсказок редактора. Если редактор
не обновился, перезапустите его TypeScript service. Код:

```ts
import * as rails from "rail_core:api";
const carts = rails.get_carts();
```

Lua-результат использует `require("rail_core:api")`. Исходники зависимости
не нужны и в вашу сборку не входят. В игре должны быть подключены оба пака.
При `npm test` VCTS копирует готовую зависимость только во временный тестовый
проект; установленный мод и локальная сборка остаются отдельными.

Пак с единственным API может просто поставлять `modules/api.lua` и
`types/api.d.ts`. Для нескольких публичных модулей и версии контракта автор пака
добавляет `types/vcts.json`:

```json
{
  "schemaVersion": 1,
  "modules": {
    "api": {"declaration": "api.d.ts", "apiVersion": 1}
  }
}
```

Имена — пути после двоеточия (`api`, `devices/motor`); декларации относительно
`types/`. Вспомогательные `.d.ts` можно импортировать из API через `import type`;
они не становятся публичными Lua-модулями. Функции в таблице Lua API обычно
объявляются с `this:void`; методы с self должны отражать реальный способ вызова.
Несколько возвращаемых значений — `LuaMultiReturn`, таблица — обычный tuple/object.

`vcts add` фиксирует точную версию `package.json` и заявленные `apiVersion`.
При обновлении VCTS останавливает сборку на несовпадении. Проверьте изменения
контракта и повторите `add`. Это проверка метаданных и TS-контракта, а не
доказательство поведения Lua: автор пакета может написать неверную декларацию.
Lua-импорты внутри внешнего пака остаются непрозрачными для сборщика: их циклы
и динамическую загрузку проверяйте интеграционным запуском.
Если папку перенесли, повторите `add` по новому пути. Автозагрузки паков из сети нет.
Транзитивные зависимости тоже подключайте через `add`, начиная с нижних уровней.
Для пака только с ресурсами используйте `add <folder> --resources`.

## У Lua-пака нет типов

Если у вас уже есть описание API, подключите его:

```sh
npm exec -- vcts add "/path/to/wire_mod" --types "vendor/wire-api.d.ts" --module api
```

Или создайте заготовку:

```sh
npm exec -- vcts types "/path/to/wire_mod" --module api
```

Она появится в `vendor/external/wire_mod/api.d.ts` и сразу будет подключена.
Заполните реальные публичные сигнатуры по документации и Lua-коду. Возможные имена
из текстового поиска в комментарии — только подсказка; это не достоверный список
экспортов. Типы аргументов, self и результаты автоматически не угадываются.
Не используйте `any` для всего API ради успешной сборки. Минимальный контракт:

```ts
export declare function connect(this:void, id:string):boolean;
```

Для каждого дополнительного модуля повторите `add --types ... --module ...`.

## Сборка прямо в игру

Заполните `packOutDirs` в конфиге:

```json
"packOutDirs": {"my_mod": "/path/to/game/content/my_mod"}
```

Это сама папка пака. Абсолютный путь macOS начинается с `/Users/`, а `Users/`
считается относительным и диагностируется как вероятная ошибка. Относительные
пути считаются от конфига. `build` и `watch` обновляют выбранные собственные паки;
`check` не пишет файлы, `test` не обновляет папки игры. Внешние зависимости VCTS
не пересобирает и не устанавливает. Ручные правки созданных Lua-файлов защищены
от перезаписи; редактируйте TS и ресурсы. Watch не перезагружает игровой мир.

## Работа над логикой и проверка

Начните с типов состояния, публичных функций и конкретных сценариев поведения.
Разделяйте подсистемы; используйте `import type` для контрактов. Runtime-циклы
запрещены. Состояние экземпляра держите в замыкании фабрики; глобальный TS-модуль
кешируется в Lua-состоянии. Генератор имеет отдельное окружение и SDK-профиль.

После правки запускайте `check`, затем проверку поведения. В `tests/start.lua`
опишите действие и наблюдаемый результат; используйте временный мир. Настройки
`test` задают сценарий, маркер успеха и JSON evidence. Движок выбирается через
`VOXELCORE_ROOT` (папка бинарника и res). Headless проверяет логику; внешний вид,
размещение и управление проверяйте в графической игре отдельно.

Для навигации по большому проекту и ошибок исполнения:

```sh
npm exec -- vcts inspect vcts.config.json my_mod:world
npm exec -- vcts explain vcts.config.json /path/to/error.log
```

Индекс содержит зависимости, пути и сигнатуры; карты ошибок относятся к конкретной
сборке. При недостатке API зависимости сначала сформулируйте отсутствующий
контракт, вместо скрытого обращения к её внутренностям. Подробные правила Scope,
Store, callbacks и lifetime находятся в поставляемом `vendor/sdk/AUTHORING.md`.

## Kompot на TypeScript

Для декларативного UI подключите готовый пак с TS-типами:
`vcts add /путь/к/vcts/integrations/kompot/pack`.
Пример находится в `examples/kompot`: компоненты, State, формы, эффекты,
списки и жизненный цикл XML-экрана. Не нужно переписывать Kompot на TS.

Kompot Lens 0.15.0 поддерживает TS-превью в VSCode. Найдите toolchain
через зависимости проекта или настройку `kompot.vctsPath`. Режим `live`
отрисовывает несохранённые изменения существующих TS-файлов; новые файлы
сначала сохраните. TypeScript API описан публичными аннотациями Kompot;
динамические экспорты могут потребовать дополнительных деклараций.

## Постепенный перенос с Lua

В `assets` можно задать `exclude`: список файлов или папок относительно `from`.
Например, `{"from":"content/raid","to":"content/raid","exclude":["package.json","modules/movement.lua"]}`
копирует ресурсы пака и оставляет место для скомпилированного TS-модуля.
Исключение папки действует на всё её содержимое. Шаблоны путей не поддерживаются.
