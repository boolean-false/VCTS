# VCTS

**TypeScript SDK и инструменты разработки контент-паков и проектов для VoxelCore.**

VCTS компилирует TypeScript в Lua для штатного VoxelCore, даёт подсказки API
в редакторе и помогает собирать, проверять и устанавливать контент-паки.
Движок устанавливается отдельно.

## Возможности

- Типы API VoxelCore с описаниями на русском и отдельными профилями для клиентских, серверных и генераторных скриптов.
- Готовые шаблоны контент-паков и проектов.
- Сборка TS-модулей, компонентов, генераторов и обработчиков XML-интерфейсов.
- Автоматическая пересборка при изменениях и установка паков в папку проекта.
- Подключение внешних Lua-паков и их TypeScript-контрактов.
- Диагностика ошибок с привязкой к исходному TypeScript и проверки в движке.
- Командная строка и интерактивное меню в терминале.

## Быстрый старт

Нужны **Node.js 22+** и отдельная установка **VoxelCore >= 0.32.0**.

Скачайте VCTS и выполните в его папке:

```sh
npm ci
node tools/vcts.cjs init /path/to/my_pack --kind pack --id my_pack
```

Для проекта замените `--kind pack` на `--kind project`.
Затем перейдите в созданный проект:

```sh
cd /path/to/my_pack
npm install
npm run check
npm run build
```

В созданном проекте исходники находятся в `src/<id>`, настройки
в `vcts.config.json`, а результат сборки появится в `build`.
Откройте проект в VS Code или WebStorm, чтобы использовать типы SDK
и подсказки API.

## Команда `vcts` в терминале

После `npm ci` выполните один раз из папки VCTS:

```sh
npm link
```

Теперь команда `vcts` доступна из любой папки. Без аргументов она открывает
меню, а `vcts --help` показывает список команд. Например:

```sh
vcts init /path/to/my_pack --kind pack --id my_pack
cd /path/to/my_pack
vcts
```

Если на macOS/Linux нет прав на глобальную папку npm, используйте:

```sh
npm_config_prefix="$HOME/.local" npm link
export PATH="$HOME/.local/bin:$PATH"
```

Добавьте строку `export PATH="$HOME/.local/bin:$PATH"` в настройки оболочки
(`~/.zshrc` для zsh или `~/.bashrc` для bash), чтобы команда работала и в новых
терминалах. Если `vcts` не находится, проверьте, что папка с командами npm
добавлена в `PATH`.

Без глобального подключения в созданном проекте после `npm install`
можно вызвать `npm exec -- vcts`.

## Windows

В PowerShell или командной строке выполните `npm ci` и `npm link` из папки VCTS.
Для создания контент-пака используйте Windows-путь:

```powershell
vcts init "C:\Projects\my_pack" --kind pack --id my_pack
cd "C:\Projects\my_pack"
npm install
npm run check
npm run build
```

Для проекта укажите `--kind project`. Пути с пробелами заключайте в кавычки.
Если PowerShell блокирует `npm.ps1` или `vcts.ps1`, вызывайте `npm.cmd`
и `vcts.cmd` либо используйте командную строку Windows.
Если команда не найдена, добавьте в `PATH` папку, которую показывает
`npm config get prefix`, и откройте новый терминал.

Для запуска тестов укажите папку установленного VoxelCore с `res`.
Автоматический поиск установки на Windows пока не настроен:

```powershell
$env:VOXELCORE_ROOT = "C:\Games\VoxelCore"
npm test
```

По умолчанию VCTS ищет `VoxelCore.exe`. Если исполняемый файл называется иначе,
укажите его полный путь в `VOXELCORE_BIN`:

```powershell
$env:VOXELCORE_BIN = "C:\Games\VoxelCore\VoxelEngine.exe"
```

В JSON-конфигах используйте пути вида `C:/Projects/my_pack` или экранируйте
обратные слеши: `C:\\Projects\\my_pack`.

## Работа с проектом

Выполняйте эти команды из папки созданного контент-пака или проекта:

| Команда | Назначение |
| --- | --- |
| `npm run check` | Проверить типы и настройки без записи сборки |
| `npm run build` | Собрать проект |
| `npm run watch` | Пересобирать проект при изменениях |
| `npm test` | Запустить сценарий проверки в VoxelCore |
| `npm exec -- vcts` | Открыть интерактивное меню |

Для тестов можно указать `VOXELCORE_ROOT`: папку с бинарником движка и `res`.
Чтобы сборка обновляла установленный пак, задайте `packOutDirs` в конфиге.
Подключение зависимостей и настройка сборки описаны
в [руководстве VCTS](VCTS_GUIDE.md).
