# VCTS 1.0 — TypeScript для VoxelCore

Готовая первая версия инструментов для модов и отдельных игр на VC 0.32.1.
TypeScript собирается в LuaJIT Lua с учётом загрузчика VC. Исходники движка менять
не требуется. Исходные моды пользователя остаются отдельно от примеров VCTS.

Есть прямые типы API, фабрики скриптов/компонентов/генераторов/layout, небольшой
авторский слой, шаблоны, единый конфиг, watch, позиции ошибок в TypeScript и
индекс модулей. Это основа для больших проектов; размер контекста нейросети сам
язык не устраняет. Явные границы модулей, контракты и индекс позволяют работать
над выбранной частью программы.

## Начать

[Короткое руководство для автора и нейросети](VCTS_GUIDE.md) описывает создание
пака, внешние Lua API, ресурсы, сборку, тесты и установку. Оно копируется в каждый
новый проект вместе с подробным `vendor/sdk/AUTHORING.md`.

Нужен Node.js 22 или новее; установите зависимости в этой папке:

Для команды `vcts` из любой папки один раз подключите локальную копию с GitHub:

```sh
npm ci
npm link
vcts
```

Если глобальная папка npm недоступна для записи, на macOS/Linux можно подключить
VCTS в пользовательский каталог:

```sh
npm_config_prefix="$HOME/.local" npm link
export PATH="$HOME/.local/bin:$PATH"
```

Для следующих запусков добавьте эту строку `export PATH` в настройки своего
терминала (например, `~/.zshrc`). Ссылка ведёт на скачанную папку VCTS; при её
перемещении повторите подключение.

Без аргументов в интерактивном терминале открывается TUI. Стрелки или `j/k`
выбирают действие, Enter открывает его, Esc возвращает назад, Ctrl+C выходит
из меню. В формах Esc/Ctrl+C отменяют ввод, Tab дополняет пути. В папке мода
или её подпапке проект определяется автоматически. Можно создать или открыть
проект, проверить и собрать его, запустить тесты/watch, подключить Lua API,
настроить установку и просмотреть сигнатуры. В watch `Q`/Esc/Ctrl+C останавливают
наблюдение и возвращают в меню.

Вместо глобального подключения доступны `npm run vcts` из папки VCTS или
`npm exec -- vcts` из установленного проекта. Явная команда `vcts ui` открывает
тот же интерфейс. Без TTY запуск без аргументов выводит справку и не ждёт ввода.
Обычные команды CLI продолжают работать для скриптов и нейросетей.

Для создания проекта командой:

```sh
npm ci
node tools/vcts.cjs init /path/to/new-mod --kind mod --id mymod
node tools/vcts.cjs init /path/to/new-game --kind game --id mygame
```

В новой папке выполните `npm install`. Затем доступны:

```sh
npm run check
npm run build
npm run watch
npm test
```

Можно обходиться без установки зависимостей шаблона и запускать CLI отсюда:

```sh
node tools/vcts.cjs build /path/to/new-mod/vcts.config.json
node tools/vcts.cjs test /path/to/new-mod/vcts.config.json
```

`build/content/<pack>` — обычный контент-пак VC. У игры `build` также содержит
`project.toml`; запуск VC с `--project /path/to/new-game/build` использует его
`base_packs`. Шаблон игры имеет собственный блок, текстуру и TypeScript-генератор,
и проверяется **без `base`**. Пак `core` остаётся частью движка.

Шаблон ссылается на локальную установку toolchain через `file:` в package.json.
При переносе на другой компьютер обновите эту ссылку и путь к runtime. Публикация
пакета в npm в эту версию не входит.

## Сборка и диагностика

В папке своего проекта выполните `npm exec -- vcts add /path/to/content/rail_core`.
VCTS находит публичные типы, настраивает редактор и разрешает
`import * as rails from "rail_core:api"`. Готовый пак остаётся внешней зависимостью;
в сборке только собственные паки. `test` подключает зависимости во временном
проекте. Для Lua API без типов есть `vcts types <pack-folder>` и
`vcts add <pack-folder> --types <api.d.ts>`.
Версии паков и опубликованных контрактов фиксируются при подключении; сборка
проверяет их, наличие Lua-модулей и транзитивных зависимостей.

Новый шаблон уже содержит пустой `packOutDirs` и пояснение `$comment` с примером
пути для вашего ID пака. Чтобы `build` и `watch` сразу обновляли мод в папке игры,
заполните `packOutDirs` в `vcts.config.json`:

```json
"outDir": "build",
"packOutDirs": {
  "my_mod": "/path/to/VoxelCore/content/my_mod"
}
```

Ключ — ID пака из `units[].packs`, значение — сама папка этого пака, включая
`my_mod`, а не общая папка `content`. Можно указать абсолютный путь или путь
относительно `vcts.config.json`, например `../VoxelCore/content/my_mod`.
Указывать назначение для всех паков не обязательно.

В `outDir` остаётся полная сборка с тестовым проектом и индексом. В указанную
папку игры попадают только файлы выбранного пака, включая ресурсы и карты ошибок.
`check` ничего не записывает; `test` собирает локальный результат и не обновляет
папки из `packOutDirs`. Первое назначение должно быть новой папкой или папкой без
совпадающих файлов: существующий Lua-мод сборщик автоматически не заменяет.
Служебный файл `.vcts-generated.json` отслеживает созданные файлы; ручные правки
защищены от перезаписи, устаревшие файлы сборки удаляются, остальные сохраняются.

`vcts.config.json` объединяет несколько независимых TypeScript-программ.
Так генератор получает свой набор глобальных функций, а UI — свой. Конфиг имеет
JSON Schema для подсказок редактора. Поля `packs.public` и `packs.dependencies`
задают разрешённые межпаковые импорты; циклы runtime-импортов запрещены.

Сборщик переписывает импорты в `require("pack:module/path")`, создаёт минимальный
набор помощников TSTL для каждого пака, копирует ресурсы и генерирует точки входа.
Фабрика выполняется в окружении экземпляра; импортированный модуль кешируется.
Подробности загрузчика: [REQUIRE.md](design/REQUIRE.md).

```sh
node tools/vcts.cjs inspect examples/starter-game/vcts.config.json
node tools/vcts.cjs inspect examples/starter-game/vcts.config.json gamekit:world
node tools/vcts.cjs explain examples/starter-game/vcts.config.json /path/to/error.log
```

`project-index.json` содержит пути исходников, зависимости и сигнатуры экспортов.
`*.lua.map` переводят строки ошибок обратно в TypeScript и содержат снимок исходника.
Карты проверяются по хешу Lua; изменение исходника после сборки явно отмечается.
Карты используют абсолютные пути разработки. Для распространения игры их можно
отключить через `sourceMaps: false` в каждой unit.

Watch пересобирает при изменениях. Ошибка проверки сохраняет прошлый результат.
Сборщик не перезаписывает изменённые вручную или чужие файлы, отслеживает свои
выходные файлы и удаляет устаревшие. Watch не перезапускает открытый мир автоматически.
Сначала исправьте сборку, затем используйте штатную перезагрузку VC.

## Проверка и границы

```sh
npm test
```

Общая команда проверяет сборку, загрузчик VC, типы, владение файлами, watch,
диагностику и поведение в актуальном headless runtime. Результаты сохраняются в
`build/logs/v1-summary.json` и отдельных `*-evidence.json`. Все тестовые миры
создаются во временных папках и удаляются; пользовательские сохранения не используются.

По исходникам объявлены **637/637 найденных публичных функций**, **40/40
зарегистрированных callbacks скриптов**, **16/16 callbacks компонентов**,
**4/4 callbacks генератора**, **4/4 layout callbacks** и **40/40 методов
перечисленных userdata**. [Инвентаризация](sdk/api/COVERAGE.md) отдельно учитывает
методы Lua-объектов. Это не обещание 100% всего API движка: динамические экспорты,
стандартный LuaJIT и exports всех `core:*` модулей имеют отдельные границы.
Наличие типа и проверка наличия функции не доказывают все её режимы работы.

В headless проверяются логика, сеть, генерация, Canvas, сохранения и компоненты.
Реальная отрисовка, действия мышью в UI и звук через устройство остаются
непроверенными. Метатаблицы UI и способ вызова обработчиков проверяются отдельно
на LuaJIT с настоящим Lua-кодом VC и подставленным backend.

По умолчанию используется выбранный runtime:
`~/Library/Application Support/vlauncher/runtimes/0.32.1-macos-aarch64`.
Другой путь задаётся через `VOXELCORE_ROOT` или `VOXELCORE_BIN`.
Аудит исходников использует `VC_SOURCES`; для обычной сборки и теста проекта
достаточно поставляемой инвентаризации и бинарника.

Закреплённые версии: TypeScript 6.0.2, TypeScriptToLua 1.37.1,
language-extensions 1.19.0. Старый эксперимент с накопителем остаётся доступен
через `npm run build:demo` и `npm run test:demo`; его описание находится в `design/`.

## Доступность примеров при проверке

`npm test` проверяет SDK, компилятор, загрузчик и примеры, исходники которых
есть в рабочей копии. При отсутствии `examples/railcore` его проверка и
зависящий от неё `external-api` явно отмечаются как недоступные в выводе
и в `build/logs/v1-summary.json`. Они не входят в число успешных проверок.

`npm run test:full` требует исходники RailCore и завершается ошибкой, если
они отсутствуют. Ошибки существующего примера не пропускаются.
